## 1. Current approved decision and observed mismatch

- Historical P1 Implementation Pack v1.0, `docs/p1/v1.0/P1_TEST_PLAN.md`, P1-T30: "*No P2+ module, network call, LLM, Telegram, marketplace, queue/worker, dataset-row table or API service exists.*"
- Historical `tests/p1/test_p1.py::test_T30_p1_scope_audit` walks **all** `src/vde/**/*.py` and forbids, among other imports, `csv` and `openpyxl`.
- P2 Implementation Pack v1.0 explicitly authorizes a `src/vde/ingestion/` CSV/XLSX reader implemented with stdlib `csv` and pinned `openpyxl`. P2 Gate B requires 42/42 P1 regression PASS.
- PR #2 evidence: 2026-10-11, code commit `151e25867339785ed0cbe64230c05ec8fa551a78`, `docs/p2/validation/p1-results.xml`: **41 PASS, P1-T30 FAIL** because required `openpyxl` was found in P2 code. Separate P2 run: 49 PASS, 4 FAIL, T54 NOT_RUN; RSS NOT_RUN.
- This is a **phase-boundary defect in the audit**, not permission for new product scope or a defect proven in P1 runtime.

## 2. Approved change

1. **Retain P1-T30, its test ID and its negative checks.** Amend its scope to the explicitly enumerated **P1-owned modules/subpackages** from the validated P1 runtime, not the whole future application tree. Use a stable allowlist of paths, or an equally explicit source-boundary policy; preserve checks for P1-disallowed dependencies/integrations and unchanged P1 persistence/approval/recovery boundaries.
2. The integration entry point `src/vde/app.py` may import approved P2 UI and is therefore **not** considered a frozen P1-only implementation for the P1-T30 import audit. Do not treat this as a general exemption for network, LLM, automation or P3+ behavior.
3. **Add or strengthen P2-T40/full-application scope audit** over all application source and dependencies, validating the Pilot Slice V1 allowlist, absence of P3–P6, LLM, URL/API/JSON ingestion, Telegram, marketplace automation, queues/workers, unauthorized services, ORM, migrations, dataset-row tables and arbitrary-code execution. Audit any new imports and repository changes as well as known forbidden patterns. A P1-path-only negative audit alone is insufficient.
4. Record the normative test-boundary interpretation in a **versioned amendment** and traceability mapping referring to this CR; preserve the original P1 v1.0 Pack as an immutable historical artifact. P0 schemas/contracts and P1 production runtime remain unchanged.
5. All 42 P1 regression IDs must still run and pass. No `skip`, `xfail`, removal, monkeypatch to bypass the audit, blanket silencing, or weakened assertion solely to make counts green.

## 3. Reason, evidence, impact and risks

- **Business objective:** unblock completion of the approved minimal P2 ingestion needed for a paid CSV/XLSX workflow without expanding the product.
- **Scope:** unchanged; test boundary only.
- **Architecture / persisted schema / versioning / Approval / whitelist:** unchanged; no P0/P1 production code, SQLite migrations, new integrations or arbitrary-code pathways authorized.
- **Fixtures:** binary P0/P2 reference fixtures remain immutable; add test fixtures for scope-audit coverage if required.
- **Schedule:** small targeted test/traceability amendment, then correct three other documented P2 failures and perform full runtime validation. This does not waive RSS measurement.
- **Risk:** an over-narrow P1 audit could silently permit prohibited dependencies in later stages. **Mitigation:** explicit P1-path allowlist plus a P2 whole-tree audit, with negative cases for new forbidden modules and integrations.
- **If rejected:** P1-T30 continues to reject approved P2 imports; simultaneous P2 reader implementation and 42/42 P1 PASS is impossible under current acceptance, so P2 Gate B remains blocked.
