**Status:** DEFERRED

## Current approved rule

P0 `state_transition_rules.md` permits `APPROVED → EXECUTING` or `APPROVED → CANCELLED` only. `APPROVED → READY_FOR_APPROVAL` is not allowed. Approval selection changes create new immutable versions and require current exact approvals; no P3 after-APPROVED edit pathway is approved.

## Proposed but deferred change

Allow an operator to reopen an APPROVED Order directly for new Brief/Spec confirmation before execution. This would modify the P0 state graph, fixtures, tests and approval preconditions and is unnecessary for the initial paid Pilot slice.

## Rationale and impact of deferral

- Preserves validated P0 semantics, no new SQLite migration, no approval bypass or P3 workflow branch.
- User cannot immediately re-edit an APPROVED Order in P3; this UX restriction is explicitly accepted for the Pilot.
- Revisit only if a real paid order demonstrates that this blocked transition is essential, then submit a fresh scoped CR and rerun affected regressions.

**No P0 document, fixture or transition may be changed under this CR's deferred status.**
