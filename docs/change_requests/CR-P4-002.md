# CR-P4-002 — Correct P4-T13 source-row oracle

**Status:** APPROVED (owner-confirmed in implementation chat, 2026-10-30).  
**Date:** 2026-10-30.  
**Scope:** P4 acceptance amendment only; preserve approved ZIP and all P0/P1/P2/P3 files.

## Observed conflict

The immutable approved P4 v1.0 archive, `P4_TEST_PLAN.md`, P4-T13, says that a full-row read of P0 P-B sheet `Orders` must yield **6 columns and 3 logical data rows**.

At approved repository baseline `7685110506d115805c473b064752f86e9e5c045b`, the actual frozen P0 `pecs/pilot_slice_v1/fixtures/P-B_xlsx_sheet/input_orders.xlsx` has **4** data rows: O-003, O-001, O-002, and a second O-002. Its `input_preview.json` independently lists those same four rows. The approved seven-operation transformation removes the duplicate and produces the **3** output rows required by P0 and P4-T42. Reading three source rows would silently omit real source data.

Actual independent read before implementation: openpyxl 3.1.5, `read_only=True`, `data_only=True`, selected sheet `Orders`: six headers, four data rows; P0 input preview count four. No source file was changed.

## Minimal requested disposition

Approve a versioned P4 test-plan/traceability amendment: P4-T13 expects **6 columns and 4 source data rows**, with exact order/cached values from frozen P0. P4-T42 continues to require **3 final transformed rows**. Keep T13/T42 identifiers, all source bytes, all other oracles, the approved P4 ZIP, the full-row reader policy and P0/P1/P2/P3 unchanged. Add no operation, dependency, schema or state transition.
